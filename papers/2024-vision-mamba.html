一句話總結

把影像切成 patch 序列、加上位置編碼，用「雙向」Mamba block 取代 self-attention，得到比 DeiT 更準、在高解析度下更省資源的純 SSM 視覺骨幹。

要解決的問題

  • ViT 在高解析度下太貴：self-attention 讓高解析度影像的速度與記憶體成本快速上升。
  • Mamba 直接搬到視覺有兩個問題：（1）單向建模——原版 Mamba 是因果掃描，但影像沒有「先後」，每個 patch 都需要看到全圖；（2）缺乏位置感知——視覺資料對位置很敏感。
  • 目標：證明視覺表徵學習不一定需要 self-attention，做出通用、純 SSM 的視覺骨幹。

方法重點

  1. Patch 序列化 + 位置編碼：和 ViT 一樣把影像切成 patch、線性投影成 token，並加上 position embedding 補足位置資訊。
  2. 雙向 Mamba block（bidirectional SSM）：同一串 token 分別做正向與反向的 selective SSM 掃描，再合併，讓每個 token 都能接收前後兩側的資訊。
  3. Class token：沿用 ViT 用 class token 做分類；論文中 class token 插在序列的中間位置 待確認。
影像 → 切 patch → 線性投影 + 位置編碼（+ class token）→ 堆疊 L 層 Vim block（每層：normalization → 正向 SSM 與反向 SSM 兩支 → 合併 → residual）→ 取 class token → 分類頭。

實驗與結果

  • 任務：ImageNet 分類、COCO 物件偵測、ADE20k 語意分割。
  • 主要結論：三個任務上表現都優於 DeiT。Abstract
  • 效率：處理高解析度影像時，速度與 GPU 記憶體都明顯優於 DeiT。具體倍數與解析度見論文 Fig. 1 待確認

優點與限制

優點

  • 純 SSM，沒有 attention，解析度越高優勢越明顯。
  • 雙向掃描這個設計很簡單，容易搬到其他模態。
  • 可當作偵測、分割的骨幹，通用性已被驗證。

限制

  • 2D 影像被攤平成 1D 後，空間上相鄰、但在序列中距離很遠的 patch 之間，關係較難建模。
  • 只處理靜態影像，沒有時間維度。

與我研究的關聯

  • VideoMamba 直接以 Vim 的雙向 block 為基礎，所以這篇是理解 VideoMamba 架構的前置知識。
  • 「攤平後相鄰關係被拉遠」的問題在影片中會更嚴重（多了時間軸）；在雙人互動中，兩個人的 token 可能在序列中相距很遠，這可能影響互動關係的建模。

待解問題與下一步

  • 確認 class token 的位置設計，以及作者對不同位置的消融實驗結果。
  • 補上 Fig. 1 的具體速度與記憶體數字。
  • 比較其他 2D 掃描策略（例如多方向掃描）的論文，看是否比雙向更適合影像。

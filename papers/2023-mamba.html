一句話總結

讓 SSM 的參數隨輸入改變（selective），再用硬體感知的掃描演算法補回效率，得到線性複雜度、品質接近 Transformer 的序列骨幹。

要解決的問題

  • Attention 太貴：Transformer 的 self-attention 對序列長度是二次方成本，長序列（長文本、長影片）在計算與記憶體上都吃不消。
  • 次二次方替代品品質不夠：linear attention、gated convolution、RNN、結構化 SSM（如 S4）雖然快，但在語言這類離散、資訊密集的資料上表現不如 attention。
  • 關鍵弱點：作者認為這些模型是「線性非時變（LTI）」的，參數不隨內容改變，因此無法做以內容為依據的推理（content-based reasoning）——例如該記住哪個 token、該忽略哪個。

方法重點

  1. 選擇性 SSM（selective SSM，S6）：把離散化步長 Δ 以及投影矩陣 B、C 改成「由當前輸入計算」，模型就能依內容決定要保留或遺忘狀態中的資訊。代價是模型變成時變的，不能再用卷積形式一次算完。
  2. 硬體感知演算法（hardware-aware scan）：改用遞迴掃描（recurrent scan），並做 kernel fusion——在 GPU 的 SRAM 中完成離散化與掃描，不把展開後的大狀態寫回 HBM；反向傳播時用重算（recomputation）省記憶體。論文表示其實作在 A100 上比先前方法最多快 3 倍。
  3. 簡化的 Mamba block：把先前 SSM 架構（H3）的 block 與 Transformer 的 MLP block 合併成單一同質 block，整個網路就是這個 block 重複堆疊，沒有 attention，也沒有獨立的 MLP block。
h_t = Ā_t · h_{t-1} + B̄_t · x_t # 狀態更新（Ā, B̄ 由 Δ_t 離散化而來） y_t = C_t · h_t # 輸出 Δ_t, B_t, C_t = f(x_t) # ← selective：參數由輸入決定
輸入 x → 線性投影分成兩路：一路經過 1D 卷積 + SiLU + selective SSM，另一路經過 SiLU 當作 gate → 兩路相乘 → 線性投影輸出。整個模型由這個 block 加上 residual 與 normalization 堆疊而成。

實驗與結果

  • 效率：推論吞吐量約為 Transformer 的 5 倍，且隨序列長度線性擴展；在真實資料上，序列長到百萬級時效能仍持續提升。Abstract
  • 語言建模：Mamba-3B 優於同尺寸的 Transformer，並與兩倍大的 Transformer 相當（預訓練與下游評估皆是）。Abstract
  • 音訊與基因體：超越 SaShiMi、Hyena、Transformer 等先前 SOTA。Sec. 4
  • 合成任務：在 Selective Copying、Induction Heads 上驗證選擇機制的必要性，後者可外推到遠長於訓練時的序列。具體數字 待確認

優點與限制

優點

  • 訓練與推論都是線性複雜度。
  • 推論時每步常數時間，不需要像 Transformer 一樣存 KV cache。
  • 架構簡單、同質，容易堆疊與擴展。

限制

  • 掃描是 1D、因果（單向）的；用在影像 / 影片時，必須另外設計「怎麼把 2D/3D 攤平」與「方向」。
  • 失去卷積形式後依賴客製 CUDA kernel，移植與部署較麻煩。
  • 本篇主要驗證語言、音訊、基因體，沒有直接處理視覺。

與我研究的關聯

  • 影片 token 數約為「幀數 × 每幀 patch 數」，長影片用 attention 成本很快爆炸；Mamba 的線性複雜度是把它用在長影片動作辨識的主要動機。
  • 選擇機制（依內容決定記住或忽略）在影片上可以理解為「自動挑關鍵幀 / 關鍵區域」，可能適合動作只占影片一小段的情況。
  • 本篇是後面 Vim、VideoMamba 的基礎，先理解 Δ、B、C 的角色，之後讀改良版本比較容易。

待解問題與下一步

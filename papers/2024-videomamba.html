一句話總結

把 Vim 的雙向 Mamba 延伸到時空 token，並用自蒸餾解決放大時的 overfit，做出短影片、長影片都「更好、更快、更省」的純 SSM 影片模型。

要解決的問題

  • 兩大挑戰：短片段內的大量時空冗餘（local redundancy），以及長影片中複雜的時空依賴（global dependencies）。
  • 3D CNN：擅長處理局部冗餘，但難以建模長距離依賴。
  • Video Transformer：能建模全域依賴，但 attention 的二次方成本讓長影片、高解析度難以負擔。
  • UniFormer 等混合方法：試圖結合兩者，但在長影片上仍有困難。作者的問題是：Mamba 能不能在影片理解上做好？

方法重點

  1. 純 SSM 影片架構：用 3D patch embedding 把影片切成時空 token，加上空間與時間位置編碼，堆疊雙向 Mamba block（承襲 Vim）。
  2. 時空掃描順序：3D token 要攤平成 1D 序列，論文比較了多種掃描方式（空間優先、時間優先等）。我讀到的結論是 spatial-first 雙向掃描表現最好 待確認。
  3. 自蒸餾（self-distillation）：作者發現純 Mamba 模型放大時容易 overfit，因此先訓練較小的模型當 teacher，再用它的特徵引導大模型訓練，讓模型在不依賴大規模資料預訓練的情況下也能擴展。
  4. Masked pretraining：也探討了遮罩預訓練策略（遮罩方式、對齊層、遮罩比例）對短影片理解的影響。細節 待確認
影片（T 幀）→ 3D patch embedding → 時空 token + 空間 / 時間位置編碼（+ class token）→ 依 spatial-first 順序攤平 → 堆疊雙向 Mamba block → class token → 分類頭。

實驗與結果

論文整理出 VideoMamba 的四項核心能力：

  • 視覺領域的可擴展性：靠自蒸餾，不需大規模資料集預訓練就能放大模型。
  • 對短期動作敏感：能辨識只有細微動作差異的短期動作。
  • 長影片理解：相較傳統 feature-based 方法有明顯進步。
  • 多模態相容：在多模態情境下也表現穩健。Abstract
  • 效率：論文稱在短期與長期影片理解上都「更好、更快、更省」；效率測試在 A100-80G、batch size 128 下進行。Fig. 1
  • 各資料集準確率：Kinetics-400、Something-Something V2 等具體數字尚未整理 待確認

優點與限制

優點

  • 線性複雜度，可以塞進更多幀、更高解析度。
  • 短影片與長影片用同一套架構。
  • 程式碼與預訓練權重公開，適合當 baseline。

限制

  • 放大時需要自蒸餾等額外技巧，訓練流程比較複雜。
  • 攤平順序是人為設計的，時空相鄰的 token 在序列中仍可能相距很遠。
  • 以整段影片為輸入，沒有顯式建模「人」這個單位，對多人互動不一定友善。

與我研究的關聯

  • 這篇是研究主軸的直接 baseline：Mamba 做影片動作辨識。
  • 雙人互動辨識需要建模「兩個人之間」的關係，但 VideoMamba 的 token 是以 patch 為單位，兩人的 token 在掃描序列中可能距離很遠。可能的方向：以人為中心的 token（person-centric tokens）、結合骨架（skeleton）輸入，或設計讓兩人 token 交錯的掃描順序。
  • 「對細微動作差異敏感」這點對互動類動作（例如握手 vs. 擊掌）可能有幫助，值得驗證。
